# MetroTRK stepping requests: 8011CBF4..8011CCEC

Status: isolated, relocation-aware byte match; not source credit until the normal native build and original DOL hash checks pass.

`src/MetroTRK/targimpl_step_retry.c` reconstructs the existing C ABI entries `TRKTargetStepOutOfRange` (128 bytes at 8011CBF4) and `TRKTargetSingleStep` (120 bytes at 8011CC74). Unsupported step-over requests return 0x703. Supported requests store the mode/count or range, enable the saved CPU trace bit, conditionally decrement the remaining count, and clear the target stopped flag. Both entries retain their current external names. The accepted command handler's declarations and callers already use these argument and return types.

The private step-state layout establishes active at 0, a byte type at 4, count at 8, range endpoints at C and 10, and total size 14 hex. CPU and target views establish only saved MSR at 1F8 and stopped at 98. Their full original storage remains external: gTRKStepStatus at 802CFE3C (20 initialized bytes), gTRKCPUState at 8033AB28 (430 hex BSS), and gTRKState at 8033AA84 (A4 hex BSS). No globals or padding are emitted or transferred by this source.

## Observed-access qualification

The native code explicitly stores the type byte, then reloads that same byte once before comparing it against 0 and 16. The source preserves this access through a private `volatile u8 type` member and one cached `u32` read in the inline stepping helper. This is an observed-access reconstruction, not proof that the complete original translation unit declared the field volatile. In particular, the audit found no independent asynchronous writer of the type byte.

The shared-state evidence is narrower and concrete. The command handler invokes these request entries; the main event loop handles both request events and queued breakpoint/exception events; `TRKTargetInterrupt` invokes `TRKTargetCheckStep`, whose trace handling reads the type/count/range and may invoke the same stepping logic again. The native interrupt/event and swap paths save or restore the debugger/target CPU state. This supports preserving the observed read of shared debugger state, while leaving original declaration provenance uncertain. Parent review approved freezing this inference explicitly; independent read-only review reached the same bounded conclusion.

The old `targimpl.c`, accepted split sources and headers, and previous research are unchanged. Compiler propagation options were tried first: normal O4,p and noprop emitted 232 bytes; nocse emitted 240; bounded O2/O3 variants remained short. A volatile type read twice emitted 256, and broad global qualification 264. A cached byte emitted the correct 248-byte extent but 30 instruction differences; a cached unsigned 32-bit value emits every native instruction. The `qualified_cached_type_*` diagnostic files accidentally widened the struct field as well as the local variable and are explicitly invalid-layout experiments, not candidates. The corrected `qualified_cached_local_type_0.c` and `_1.c` retain the byte field and match.
