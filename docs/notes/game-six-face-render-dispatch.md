# Six-face renderer dispatch

Isolated source matches `fn_8027121C` at `8027121C..802715C8`: 940 retained text bytes and 19 actual relocations. Production integration and the full original DOL hash check remain pending. The original global C identity is retained.

The routine resolves the record's Handle through the shared manager, updates a dirty world matrix from the current matrix bank, copies that matrix and clears its translation, then supplies it to the renderer. It sets position and UV arrays and obtains the parent, world and local matrices. For each of six faces, a successful external test selects a copied face Handle through virtual slot `A0`, updates renderer state, and calls the face's display list when both its data pointer and capacity are nonzero. The observed capacity check is preserved.

Only observed layouts are reconstructed. Manager entries have 16-byte stride with an object pointer at `0` and signed generation at `C`; Handles have signed generation/index fields of 8/24 bits. Distinct concrete resource, world-resource and parent-resource manager casts preserve the original repeated entry-table load. Genuine resource member getters preserve all original saved-register assignments. These are partial views, not complete recovered game classes. The renderer's nonpolymorphic prefix places its virtual pointer at `278` and flags at `2D0/2D2`; the source does not construct that partial renderer.

The local Handle copy uses the established native `Handle_801F7F10` constructor/destructor and one zero-initializing base layer. The copied Handle remains alive through the virtual call and is destroyed immediately afterward. Removing that automatic lifetime and explicitly cleaning up trivial storage loses the native saved-pointer alias, so those failed variants remain private.

GC1.3.2 with `-O4,p -inline auto -Cpp_exceptions off -use_lmw_stmw on` emits only a 1,112-byte `.text` allocation. Its retained prefix is exactly 940 bytes. Two unreferenced weak destructor backups occupy the trailing 88 and 84 bytes and have four additional actual relocations. Their complete raw bytes, symbols, offsets, bindings and nonallocated metadata are inventoried; they receive no credit. The immutable strict verifier confirms no retained allocation references either backup. A scan of all current active original/source ELF inputs finds no existing binding for their unique names. Full production acceptance must separately require native map discard rows and final ELF absence for both backups; final ELF absence alone is insufficient.

The original exception, constructor and destructor tables were audited over their full ranges, including descriptors, padding and trailing zeros. They contain no references to this function. Every byte offset in all initialized DOL data sections was scanned for pointers into the retained extent. No data, BSS, startup tables, padding or other original functions transfer to this source. The shared global context, matrix functions, native Handle operations, floating literal and GX functions remain externally owned. This is an independently owned text-only split, not a claim to recover the complete original translation unit.

Sources, failed structural probes, fresh production compilation, all allocated-byte/real-relocation evidence and frozen hashes are in `scratch/engine_six_face_render_20261011iy`. Shared configuration, accepted source and previous research were not edited.
