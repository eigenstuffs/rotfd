# Hierarchy destructor and virtual table

`src/Game/hierarchy_destructor.cpp` recovers the native C++ destructor at
`0x80200478..0x802007D8` (864 bytes) and the compiler-generated 32-byte virtual
table at `0x802EAF40..0x802EAF60`. This is a bounded source fragment; the full
original translation-unit boundary and original class names are not established.

The object places two words before its virtual pointer at offset `8`, an owner
handle at `0xC`, six count/capacity/data lists at `0x90`, `0x9C`, `0xA8`, `0xB4`,
`0xC4`, and `0xD0`, and a related handle at `0xC0`. Native member destruction
produces the observed reverse order, including the separately recovered
`HandleList_802007D8` destructor call with the compiler's `-1` member flag. The
base destructor receives flag zero. A positive deleting-destructor flag invokes
the inherited custom `operator delete` using the existing heap at `0x801EF5C8`.

Inline typed-handle wrapper depths reproduce the original repeated null-check
branches before the common handle destructor. These class/layer names and list
roles are layout inferences, not recovered debug names. The three empty inherited
virtual slots expose no parameter information; their declarations remain minimal.
Slot `0xC` forwards one opaque machine-word argument; slot `0x1C` returns a
Boolean. These declarations affect the native symbol mapping only; all original
vtable targets are preserved exactly.

The virtual table is generated by the compiler from the actual inheritance and
virtual declarations. It contains the two null prefix words, this destructor,
and the original targets `802072A0`, `80023950`, `80023954`, `800AE2B4`, and
`80203510`. The neighboring base table at `0x802EAF60` remains original fallback.
The candidate manifest lists native names and prior original names for central
symbol integration.

`python3 scratch/game_hierarchy_destructor/verify.py` compiles with GC/1.3.2,
`-O4,p -inline deferred`, exceptions/RTTI off, and `-use_lmw_stmw on`. It applies
all 35 actual ELF relocations, verifies every byte in both allocated sections,
checks the original section addresses satisfy emitted alignment, and checks the
protected DOL SHA-1 `5da8295a79bf297ab62c620e6ac66210be1c6ef5`. Result: **864
text bytes and 32 data bytes exact**, with no extra allocated sections, emitted
weak helpers, masked instructions, or object changes. Full-DOL/native objdiff
integration passes, including complete DOL byte equality and the original-source regression audit.

The earlier explicit C-ABI destructor probe remains in
`scratch/game_hierarchy_destructor/destructor.cpp`; it emitted only 828 bytes
and is not credited. Native C++ destruction supplied the missing semantic
structure and correct register allocation.

## Signed-byte lifecycle result

The recovered hierarchy lifecycle caller establishes a signed-byte result for
`slot1C`, refining the earlier `bool` declaration. The source now uses
`signed char` consistently. Fresh isolated compiles before and after this
refinement produce identical complete object hashes; all instructions, owned
data, relocations and vtable entries remain exact. See the
[lifecycle evidence](game-hierarchy-lifecycle.md).
