## Compiler discriminator

**GC/1.3 with `-char signed` is required.** The otherwise matching GC/1.3.2 compiler changes register allocation and instruction scheduling in one small zero-digit insertion block. Under GC/1.3's unsigned plain-character default, the two stack model strings also affect character-table hoisting and persistent register allocation throughout the parser. Explicit signed plain characters on GC/1.3 resolves both differences and matches the entire source without special-purpose expressions, assembly, or optimizer barriers.

The wrappers' `value` and `abs_value` locals are `long double`, although the `strtod` result type is `double`. This preserves the distinct long-double zero constant and the double zero constant generated by the parser's `if (result)` test. Both are eight bytes on the target ABI. `-inline auto,deferred` retains `strtod` while inlining it within `atof`; deferred inlining alone leaves an unmatched call.

```sh
build/tools/wibo build/compilers/GC/1.3/mwcceppc.exe \
  -c -proc gekko -fp hardware -enum int -str reuse -common off \
  -O4,p -inline auto,deferred -use_lmw_stmw on -pool off \
  -Cpp_exceptions off -char signed -i include \
  -o scratch/msl_strtod/final.o src/MSL/strtold.c
python3 scratch/msl_strtod/check_object.py
```

Expected verification: `.text` 4,436 bytes, `.rodata` 53 emitted bytes, `.sdata2` 24 bytes; zero mismatches and 96 resolved relocations. The checker enforces the manifest's exact emitted section sizes, verifies the original DOL SHA-1, separately verifies every `external_padding` range is zero, and rejects unexpected allocated sections.
