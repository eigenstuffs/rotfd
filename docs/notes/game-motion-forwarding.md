# Motion forwarding and reset entries

Accepted matching source: the production build passes the original DOL hash,
strict allocated-byte/extent and actual-relocation checks, baseline regression
checks, generated progress verification and all 26 repository tests.

Twenty-five ordinary C++ functions reproduce 820 original text bytes and 500 owned exception/index bytes. Twenty-four forward to the original motion/action implementation; the remaining entry calls base startup and resets the embedded component. Reconstructed parameters preserve the original floating delta, vector arguments and virtual-call value arguments where the target uses them. Empty targets remain ordinary external C calls.

Strict production recompilation verifies every allocated byte and symbol extent with 76 actual relocations. Full original exception-index, descriptor, constructor and destructor tables establish one owned exception/index record per entry and no startup references. No owned data, BSS, weak helpers, padding, aliases, hand-written assembly, payload edits or symbol migrations are present.

These are partial text-only splits. Other original methods, virtual tables and registry data remain outside them. The shared declarations have twenty-five consumers. Isolated evidence is frozen in `scratch/game_motion_forwarding/final_integration.json`; central registration and complete original-DOL acceptance remain required.
