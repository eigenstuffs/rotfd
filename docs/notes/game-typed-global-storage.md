# Typed global storage

Five ordinary zero-initialized C++ storage units recover 14,160 bytes of engine BSS. They emit only `.bss` (SHT_NOBITS), with natural eight-byte section alignment, no code, constructors, relocations, or initialized data. GC/1.3.2 uses the normal Gekko hardware-FP flags with exceptions disabled and `-i src/dolphin/os`. `scratch/game_frontier_20261012_b/typed_storage.verified.json` records protected-input hashes, compiler object/source hashes, all allocated extents and exact object offsets; the main build remains the acceptance authority.

`engine_reset_typed_storage.cpp` owns `8033E738..80340ABC` (9,092 bytes). The shared drawing color is four floats initialized by existing `fn_801E1AA8`. Two registration records contain the three pointers written by `__register_global_object`: next, destructor and object. Their original broad 16-byte labels include four bytes of alignment after the 12-byte record. The first record's four-byte alignment before the naturally eight-aligned thread is inside the compiler's storage extent; the four bytes following the second record remain outside this source split.

The large record at `8033E758` contains a complete original Dolphin `OSThread` (0x318), its 0x2000-byte reset-thread stack, and a 32-byte DVD-read buffer. Main's original instructions at `801EC20C..801EC22C` pass the thread at `8033E758`, stack top at `80340A70`, and stack size 0x2000 to `OSCreateThread`; `801EC39C..801EC3A8` passes the following `80340A70..80340A90` buffer to a 32-byte DVD read. The separate `80340A90..80340AB0` buffer is used for the same 32-byte read by existing `fn_801EBE64`. These byte arrays are observed thread stack and input buffers, rather than representations of unknown object bytes. The thread layout comes from the repository's already reconstructed `OSThread_abi.h`.

`engine_box_points_typed_storage.cpp` owns `80340AC0..80340B44` (132 bytes): eight three-float box corners and three three-float axes. Existing original startup `fn_801F0E60` initializes all 33 components; existing sphere-box routines read the eight corners at a 12-byte stride. The original `lbl_80340B20` extent of 0x28 includes four following alignment bytes; its actual array extent is 0x24. `80340B44..80340B48` remains outside source ownership.

`engine_worker_threads_typed_storage.cpp` owns `80340D00..80341350` (1,616 bytes): two four-float colors initialized by original `fn_80269A30`, followed by two complete `OSThread` records. Existing `fn_80275AF4` passes `80340D20` to `OSCancelThread`. Existing `fn_80278EC4` passes `80341038` to `OSCreateThread`, and existing card operations suspend/resume that same thread. The 16 bytes at `80341350..80341360` are following alignment, not part of the second thread and not source credit. No additional padding object or enlarged thread is introduced.

These are partial typed storage units, not claims to completed original translation units. Original initialization functions and all their owned code/data retain their existing ownership.

`python_resource_cache_typed_storage.cpp` owns `802F3460..802F40F8` (3,224 bytes). Existing `fn_80020C78` zeros the three-word dynamic resource array and calls `__construct_array` twice with element size 8 and count 200, at offsets 0x18 and 0x658 from the registration-record base. `fn_80020500` and `fn_800208A8` search the two caches with an eight-byte stride, comparing a name hash at offset zero and retrieving the cached pointer at offset four. Existing `fn_8001F90C` establishes the resource-array layout as signed count/capacity followed by a pointer to 72-byte name/hash/value records. The 12-byte registration record has no synthetic padding.

`early_light_colors_typed_storage.cpp` owns `802F41A8..802F4208` (96 bytes), two arrays of three four-float colors. Existing original startup `fn_800AE2B8` writes all 24 float components, as established in `game-engine-scalar-last.md`, and `fn_800AD990` reads them. Startup matching is still separate work. The intermediate `802F40F8..802F41A8` storage remains external; its formatting-buffer capacities cannot be recovered confidently from unbounded sprintf calls alone.
