# CodeWarrior C++ construction and exception support

`src/Runtime/NMWException.cpp` reconstructs the complete retained translation unit at `0x8011EE74..0x8011F460`: nine functions and 1,516 code bytes. It implements array construction/destruction, the partial-array cleanup class, throw/catch type matching, and the default unexpected/terminate handlers.

The source follows the [pinned Wind Waker NMWException reconstruction](https://github.com/zeldaret/tww/blob/11d6aa597a6b6218a38eff2726c841a31f851a57/src/PowerPC_EABI_Support/Runtime/Src/NMWException.cp), with its [constructor/destructor ABI header](https://github.com/zeldaret/tww/blob/11d6aa597a6b6218a38eff2726c841a31f851a57/src/PowerPC_EABI_Support/Runtime/Inc/MWCPlusLib.h). Unmodified references, comparison sources, and upstream notices remain in the reference directories. Non-retained handler setters and destroy-new-array functions are omitted. These are community reconstructions, not an official SDK source release.

The C++ class retains its real constructor, destructor, and cleanup behavior. CodeWarrior generates the 96-byte `extab` block at `0x80015E88` and 96-byte `extabindex` block at `0x8001F1E8` directly from these object lifetimes. The two static handler pointers occupy eight `.sdata` bytes at `0x80375E18`. There are no source-authored exception byte arrays or native assembly substitutes. Operator delete at `0x8011EDD4` remains an external dependency of this unit.

`python3 scratch/runtime_nmw_exception/verify.py` compiles with GC/1.3.2, `-O4,p`, `-inline auto,deferred`, `-use_lmw_stmw on`, signed chars, exceptions enabled, and the compiler's internal-runtime pragma. All 25 relocations, 1,516 instruction bytes, both exception sections, and both handler pointers match exactly. The candidate manifest records symbols, complete section ownership, flags, and hashes. Parent integration checks the final DOL separately; the already matched global destructor-chain and exception initialization units remain unchanged.
