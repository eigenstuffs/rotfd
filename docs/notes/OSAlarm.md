# Dolphin SDK alarm scheduler

`src/dolphin/os/OSAlarm.c` reconstructs six C functions at `0x800F18C4..0x800F1F24` (1,632 bytes): `OSInitAlarm`, `OSCreateAlarm`, `InsertAlarm`, `OSSetAlarm`, `OSCancelAlarm`, and `DecrementerExceptionCallback`. Its queue, system-time comparisons, periodic re-insertion, scheduler/context calls, and exception handler establish the unit identity. Source reference is the public [Melee SDK reconstruction](https://github.com/doldecomp/melee/blob/master/extern/dolphin/src/dolphin/os/OSAlarm.c); retrieved files and hashes are recorded in `reference/melee-sdk/PROVENANCE.md`.

The 80-byte `DecrementerExceptionHandler` at `0x800F1F24..0x800F1F74` remains an original fallback object. It is excluded from this source split and recovered C coverage. The research source containing its SDK register-save macro and target eight-byte stack adjustment is preserved only in `scratch/OSAlarm/with_assembly_entry.c`. Production source declares that wrapper externally and exposes `DecrementerExceptionCallback` so the original wrapper can branch into the recovered C. Both originally had static translation-unit linkage; the external linkage is solely an integration requirement of this partial split. No generated disassembly replaces a C function.

The C unit owns eight zero-initialized bytes for `AlarmQueue` at `.sbss` `0x80377900..0x80377908` and no initialized data. The target differs from the reference `OSCreateAlarm` by clearing both `handler` and `tag`; both stores are visible in the original four-instruction function. `SetTimer` is inline. Unlinked debug/check and absolute/periodic alarm APIs remain as unused static inline source, with assertions disabled.

GC/1.2.5n with `-proc gekko -fp hardware -enum int -str reuse -common off -O4,p -inline auto -Cpp_exceptions off` reproduces all C instructions. Source-order emission and this compiler's function prologues match the original SDK object. `scratch/OSAlarm/verify.py` resolves every relocation and compares directly with the DOL: `TEXT 1632 1632`. The candidate records six C functions, zero recovered assembly bytes, and explicit wrapper/callback global scopes for integration. Whole-DOL SHA-1 remains the integration check.

`OSAlloc.c` was considered first, but allocator diagnostics/references were absent from the initial presence check, and the SDK sequence runs directly from the alarm wrapper into `OSArena.c` at `0x800F1F74`. This motivated selecting a present bounded unit; it does not exclude original bytes from progress.
