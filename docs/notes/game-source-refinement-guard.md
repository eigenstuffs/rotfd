# Zero-credit native source refinement guard

Accepted matching source: the production build passes the original DOL hash,
strict allocated-byte/extent and actual-relocation checks, baseline regression
checks, generated progress verification and all 26 repository tests.

The existing callback control unit keeps all 432 original text bytes and all
four callable entries. Three callback flag units each keep 104 bytes. Their
existing source paths, split extents and original data identities remain stable.
Only the final control definition and the three single-constructor definitions
are expressed using their recovered native C++ classes.

The ordered source-history registry appends an explicit refinement edge after
all previous identifier migrations. Complete before/after sources, canonical
manifests, production/private objects, headers and historical external symbol
identities are frozen. Previous proofs remain unchanged. Initial snapshots and
protected inputs are ineligible for this refinement operation.

Both object forms independently pass the unchanged strict allocated-byte and
actual-relocation verifier. A separate invariant check requires identical raw
retained allocation bytes/types/flags/alignment and original ranges, identical
callable/object inventories under the explicit native-name map, and an identical
multiset of retained relocations including address, kind, resolved target and
addend. Duplicate references cannot disappear behind set comparison. Original
exception/startup/shutdown tables are checked against the unchanged executable.
Code and data credit must both remain zero.

Additional weak C++ destructors are explicitly inventoried with raw hashes and
relocation counts. None receives credit or may be referenced by retained code.
Production verification repeats all allocation checks, and the final ELF must
exclude every unused helper. The full DOL hash, baseline, denominator, generated
progress and repository tests remain mandatory acceptance gates.

Thirteen positive/negative guard tests cover the real preserved refinement,
retained bytes/ranges, duplicate/missing/changed relocations, callable additions
or removals, initial files, credit, frozen object corruption and canonical/source/object disagreement. The ten existing
identifier-migration guard tests also continue to pass. Guard tools and proofs
are under `scratch/continuation_20261010/`.

Four existing early constructors also keep 360 code bytes and 80 original
exception/index bytes while gaining their native constructor identities and
full factory-size opaque layouts. Together the eight refinements preserve 1,184
owned bytes. Canonical manifests must independently agree with each frozen
source/object row before any refinement is registered. The accepted proof is
`scratch/continuation_20261010/callback-native-refinement-v3/proof.json`.
Earlier unaccepted proposals remain preserved alongside their rollback record.
