# Repeated virtual reset callbacks

Twelve disjoint original C entries reconstruct 1,096 code bytes and 240 exception bytes with GC1.3.2 Gekko `-O4,s -Cpp_exceptions on -use_lmw_stmw on`. Each source owns one physical function and its original eight-byte `extab` plus twelve-byte index. No helpers, literals, tables, BSS, constructors, or destructors are emitted. All 41 actual relocations are resolved and verified; the full original executable build remains root's acceptance step.

Five 92-byte callbacks (`80044D3C`, `80045C58`, `80046D04`, `8004B914`, `8004CB64`) call the existing `fn_80256370`, invoke a virtual operation with two zero word arguments, then call `fn_802073E8(self,0,self,external_float)`. The 84-byte `8004CB10` callback omits the first call. Six 92-byte callbacks (`80048748`, `80049234`, `80049F10`, `8004AF4C`, `8004F43C`, `800506F0`) invoke the same virtual slot twice with those two zero arguments.

Private polymorphic views model only the established vtable pointer at object offset8 and the observed callable slot offsets (0x80,0x8C,0x98,0x9C). Uncalled slots are opaque declarations and emit no symbols or allocations. The virtual prototype has two separate machine-word arguments in r4/r5; a diagnostic U64 prototype placed them in r5/r6 and differed by exactly one instruction per call. Declaring the two observed words gives all original instructions and their original order, including original LR/GPR restoration. Semantic names of the virtual operations remain provisional.
