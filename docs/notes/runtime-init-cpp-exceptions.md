# C++ exception-fragment registration and native accessor boundary

`Runtime.PPCEABI.H/__init_cpp_exceptions.cpp` now contains only the two C++ registration routines: `__fini_cpp_exceptions` at `0x8011FACC..0x8011FB00` and `__init_cpp_exceptions` at `0x8011FB00..0x8011FB40`. Their original 116 code bytes are unchanged. They register the exception-index range with the runtime using the original r2 value, store the fragment identifier, and unregister it during shutdown. The local identifier begins at -2; repeated registration/shutdown follows the original sentinel checks.

The original `static asm GetR2()` body was preserved under `scratch/runtime_init_cpp/native_original.cpp` and removed from production source. The native two-instruction accessor remains original fallback at `0x8011FAC4..0x8011FACC` (8 bytes). Its `GetR2__Fv` symbol becomes global only to connect the partial C++ source to its original accessor; it originally had local linkage. This is an accounting correction, not a new C++ implementation of the accessor.

The source's exact initialized ownership is `.ctors` `0x80299920..0x80299924` (4 bytes), `.dtors` `0x80299980..0x80299988` (8 bytes), and `.sdata` `0x80375E20..0x80375E24` (4-byte `fragmentID`). Four following zero bytes at `0x80375E24..0x80375E28` are external linker alignment, not source data. Earlier source progress included both the native accessor and that alignment: the correction removes **8 code bytes, one function, and 4 data bytes from recovered-source credit**, while retaining their original bytes and denominator classifications.

GC/1.3.2 with the unchanged existing runtime flags reproduces all 116 C++ text bytes and all 16 initialized bytes. `scratch/runtime_init_cpp/verify.py` applies all 12 relocations and checks each complete allocated ELF section against the protected original DOL. The four external padding bytes are separately verified as zero. The preserved prior object demonstrates the exact removal of the leading eight-byte accessor; no ordinary registration instructions were altered. The complete handoff is `config/GSQE78/candidates/runtime-init-cpp-exceptions.json`.

The linked-source audit in `scratch/runtime_init_cpp/audit_source_asm.py` reads source paths from the current objdiff configuration and scans the entire `src` and `include` tree for `asm`, `__asm`, and `__asm__` after removing comments. After this correction, it finds no remaining executable assembly token and no non-C/C++ source path among configured source objects. The three remaining raw search hits are comments in `src/dolphin/gx/mtx.h`. Ordinary compiler intrinsics used inside reconstructed C algorithms, such as bitfield operations and the synchronization intrinsic, remain ordinary C source; this audit does not mistake them for source-authored assembly functions. The exact inventory size and configuration hash are retained in `source_asm_audit.json` because integrations continue concurrently.

The central build passes the original DOL SHA-1 and native objdiff at **116/116 C++ code bytes, 2/2 functions, and 16/16 data bytes**. The eight-byte accessor and four-byte alignment are explicitly named `NonMatching` original units. The saved four-unit baseline is unchanged: `ninja changes` therefore exposes this intentional reduction in historical source credit. The initializer-specific acceptance allowance permits only this exact documented reduction and independently asserts that both excluded ranges remain in the report with zero recovered credit. No source instructions or reference bytes regress.
