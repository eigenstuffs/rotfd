# DamageVolume lifetime and configuration

`src/Game/damage_volume_lifetime.cpp` owns the contiguous five-function range `0x800C92D4..0x800C94A8`: native constructor/destructor, initialization and base-update callbacks, and numeric configuration. The existing `DamageVolume.h` factory establishes the `0x80`-byte extent, checked by a compile-time assertion. The native base lifetime functions and original vtable remain external; a separate virtual view expresses the initialization callback's dispatch through slot `0x8C` without emitting an invented vtable.

All 468 instruction bytes, 132 exception/index bytes, four float-literal bytes, and 28 retained relocations match the original. The configuration reads the kind and mode as unsigned bytes, restricts the kind to `1..5`, and clamps magnitude to a minimum of `1.0f`. The constructor initializes that same magnitude and clears the byte at `0x79`.

Literal ownership solves the earlier five-byte floating-point register mismatch. The original float at `0x80379640` has exactly two direct SDA2 consumers, at constructor instruction `0x800C92F0` and configuration instruction `0x800C9464`. Scanning all original DOL text confirms those two uses; no aligned absolute pointer to the constant exists anywhere in the DOL. Both consumers now reside in this source unit, so the native compiler-generated four-byte literal can have local linkage. No fallback user is stranded, no synthetic reference is added, and no global alias or address patch is needed. The original address satisfies the compiler's eight-byte section alignment.
