# Container-derived Object destructor variants

Accepted matching source: the production build passes the original DOL hash,
strict allocated-byte/extent and actual-relocation checks, baseline regression
checks, generated progress verification and all 26 repository tests.

Frozen isolated handoff: 12 ordinary native C++ destructors, 3,652 retained text bytes plus 624 exact compiler-emitted exception bytes, 227 actual relocations. The original provisional `dtor_<address>` names map to compiler-native `__dt__15Object_<address>Fv` using guarded `original_symbol` entries. The full accepted source/header/assembly caller audit finds no use of the old names. Every source matches on its first isolated probe and after readable formatting in production. Parent staging, final DOL hash and regression acceptance remain required.

The functions are 0x80045AC4 (292), 0x80046B70 (292), 0x80048624 (292), 0x800490F0 (324), 0x80049DB0 (352), 0x8004B780 (292), 0x8004C9FC (276), 0x8004DBE0 (352), 0x8004F318 (292), 0x80050590 (352), 0x800529A0 (260), and 0x80071358 (276). They use the already established private container destruction view: external native Object base through offset 0x48; three-word array at 0x48; typed handle at 0x58; inline table updates for each inherited layer; then conditional object storage release. Some variants introduce one typed handle at 0x70, two at 0x70/0x74, or two at 0x80/0x84. Opaque storage establishes those observed offsets. Automatic member and base destruction preserves the exact reverse cleanup order and repeated null checks. These declarations are private offset views, without a claim to full original class names or layouts.

GC/1.3.2 uses the established container-base `-O4,s -inline auto -Cpp_exceptions on -use_lmw_stmw on` flags, hardware Gekko, with ordinary operator delete declared `throw()`. Strict production verification checks every allocated byte, all exact symbol extents, actual relocations, source SHA256 and empty recursive quoted-header inventories. Dependencies are drawn only from referenced undefined ELF symbols; compiler-owned local extab literals never become global dependencies merely because names coincide in the original symbol table.

Each destructor owns exactly 40 extab bytes and a 12-byte extabindex record. Audits read the complete original extabindex 0x80015F60..0x8001F2C0, ctors 0x80299920..0x80299980 and dtors 0x80299980..0x802999A0 tables. No constructor/destructor-table pointers, helpers, weak code, BSS, padding or other data are emitted or owned. Original functions and data outside the partial splits retain their existing ownership. Frozen manifest, proposed splits/configuration, strict verifier and ownership audit are under `scratch/game_engine_container_variants_continuation/`.
